# 新版界面

ok-gf2 的图形界面，按 [MXU](https://github.com/MistEO/MXU)（NikkeMDA 用的那套 MaaFramework 客户端）的交互和样式做：
顶栏一个工作流一个页签（每日日常 / 周常 / 推图 / 工具），任务按游戏板块分组、卡片式勾选、一键预设、右侧运行状态 / 游戏画面 / 日志，深浅色和九种强调色。
旧的 Qt 桌面界面和框架自带网页不再维护。

## 怎么打开

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| Windows 窗口（推荐） | `run_v2.bat` / 桌面快捷方式 `ok-gf2-v2.lnk` | 先 `git pull`，再跑 `tools\app_v2.py --port 8765`，用 pywebview 开原生窗口 |
| 无边框窗口 | `tools\app_v2.py --frameless` | 和 MXU 一样由界面自绘标题栏（最小化 / 最大化 / 关闭），没在 Windows 上验证过，有问题去掉参数 |
| 只起后端 | `tools\serve_web_v2.py --port 8765` | 浏览器打开 `http://127.0.0.1:8765/v2/` |

ok 框架只允许一个实例：先关掉正在跑的 ok-gf2（桌面版、`serve_web.py`、另一个 app_v2），再开。

## 界面说明

- **顶栏**：一个工作流一个页签 + 执行器状态；右边深浅色切换、设置。正在跑的那个工作流的页签上有蓝色呼吸点，切到别的页签也能停。
  - **每日日常**：一键日常（DailyTask），按游戏板块分组（邮件、活动、限时开启、活动层、公共区/委托、商城、战役推进、班组、巡录、网页社区）。
  - **周常**：WeeklyTask 的首领挑战 / 峰值推定 / 扩编实练三项，扩编实练卡片里有自己的「阵容」。
  - **推图**：ClearMapTask，一张选项卡（三种 OCR、战斗内点击自动）+「阵容 · 推图」；停在任意关卡页面点「开始推图」。
  - **工具**：独立任务，用卡片右侧的「运行」单独跑：启动一次游戏、性能诊断、调试工具、模板监控（触发任务）、测试任务。后端注册了但目录里没列的任务会自动出现在这页的「其它任务」。
- **任务列表**：分组标题可折叠，右侧显示「已勾选/可勾选数」。
  每张卡片：复选框 = 该项在这个工作流主任务里的开关；折叠时在名字后面预览选项值；点右侧箭头展开说明和选项；展开面板底部可恢复该任务默认值。
  主任务的纯选项卡（如推图设置）前面是滑杆图标，随「开始」一起生效；独立任务前面是播放图标；触发任务（模板监控）复选框是启用/停用。
  左侧竖条：蓝色呼吸 = 正在执行；蓝 = 今日已完成；橙 = 今日待重试。
- **底部工具栏**：全选 / 折叠展开 / 预设（只有有开关项 / 有预设的工作流才显示）；右边「开始日常」「开始周常」「开始推图」（运行中变红色「停止」，旁边出现暂停/继续）；工具页没有开始按钮。
- **预设**：全套日常 / 快速收菜 / 只打体力，一键改勾选项，定义在 `web_v2/public/catalog.json` 的 daily 工作流里。
- **右侧面板**：运行状态（执行器、当前任务、今日已完成/待重试）、游戏画面（抓一帧 / 每 3 秒自动）、运行日志（级别 + 关键字过滤，默认滤掉 DEBUG 和识别噪音）。
  点日志标题可以把上面两个面板折起来放大日志；中间的分隔条可拖宽。
- **设置页**：外观（主题模式、强调色）；全局设置（从各板块抽出来、对整轮生效的日常项）；框架设置（ok-script 的设置组：阵容与助战、窗口等）；关于。

所有改动即时写回 `configs/`，没有保存按钮。

## 阵容：默认 → 全局 → 板块单独设置

编队和借助战按三层取值，越后越优先：内置默认（编队1、借助战开）→ 设置页「框架设置 · 阵容与助战」→ 各板块卡片里的「阵容」小卡。

- 场景登记在 `src/core/lineup_config.py` 的 `SCOPES`（推图、竞技场、体力本、班组、尘烟前哨战、活动、扩编实练），每个场景在全局组里有 `<场景>编队`（留空 = 沿用）和可借助战场景的 `<场景>助战`（沿用全局 / 开 / 关）。数据只存这一份。
- `catalog.json` 的条目用 `lineup_scopes` 声明用到哪些场景，展开卡片就显示对应的「阵容 · 场景」小卡：编队输入框的灰字是继承来的值，助战三段按钮标出全局当前值，单独设置过会标「已单独设置」，「恢复全局」一键清掉。
- 设置页「阵容与助战」卡片底部有各场景一览，高亮和全局不一样的场景，「去设置」跳到对应板块并展开。
- 加新场景：`SCOPES` 里加一行，再在 catalog 对应条目的 `lineup_scopes` 里写上，界面不用改代码。

## 目录与板块的对应

目录在 `web_v2/public/catalog.json`：`workflows` 每项是一个页签，`task` 是主任务类名（底部「开始」跑它，null 表示只是一组独立任务）、`start_label`、`groups`、`presets`、`collect_unlisted`（把目录里没出现的任务收进来）。
`groups` 里每个 entry 有 `task`（任务类名）、`enable_key`（在主任务里的开关键，纯选项卡 / 独立任务为 null）、`keys`（显示的配置键，`"*"` 表示全部）、`lineup_scopes`、`doc`（说明）。
`global_sections` 是设置页「全局设置」的卡片。主任务里没被目录收编的键会自动出现在该页签的「其它选项」分组，不会丢。
加一个工作流 = 在 `workflows` 里加一项，不用改代码。

## 实现

- `web_v2/`：Vite + React 19 + Tailwind 4 + lucide-react + zustand + sonner，`src/` 是源码，`static/` 是构建产物（随仓库提交，Windows 上不用装 node）。
- 样式、主题（`src/themes/presets`）、表单控件、卡片 / 面板 / 设置页布局来自 MXU（AGPL-3.0，许可证见 `web_v2/third_party/MXU-LICENSE`）。
- 数据全部走 ok-script Web 模式自带的 `/api`（tasks / status / settings / logs / tools/capture / events websocket），没有改框架。
- 改界面：`cd web_v2 && npm install && npm run build`，提交 `static/`。本机联调：`npm run mock`（假后端，8765）+ `npm run dev`（5173，/api 代理到 8765）或 `npm run preview`（4173）。
- `tools/serve_web_v2.py` 把 `web_v2/static` 挂到 `/v2`；`tools/app_v2.py` 在其上套 pywebview 窗口。

## 已知限制

- 任务顺序固定按目录，不支持拖动排序（ok 的一键日常本身顺序由代码决定）。
- 没有多账户、定时执行页面；多账户相关开关在设置页「全局设置 · 日常通用」。
- 「教化」还没有实现，目录里也没列。
- 无边框模式（`--frameless`）未在 Windows 实机验证。
